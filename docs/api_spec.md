# Документация API платформы eSchool (eschool.center)

Спецификация получена в результате реверс-инжиниринга официального Android-клиента (`ru.spb.itstrategy.mobilejournal`), веб-интерфейса `app.eschool.center` и анализа открытых библиотек.

## Базовый URL
`https://app.eschool.center/ec-server`

---

## 1. Аутентификация

### 1.1. Вход в систему (Login)
* **Эндпоинт:** `POST /login`
* **Content-Type:** `application/x-www-form-urlencoded`
* **Параметры формы (Form Data):**
  * `username` (строка): логин пользователя (ученика или родителя).
  * `password` (строка): SHA-256 хэш исходного пароля в hex-формате (`MessageDigest.getInstance("SHA-256")`).
  * `device` (опционально, JSON-строка): метаданные устройства:
    ```json
    {
      "cliType": "android",
      "cliVer": "1.0.0",
      "pushToken": "",
      "deviceName": "Android Device",
      "deviceModel": "Pixel",
      "cliOs": "Android",
      "cliOsVer": "14"
    }
    ```
* **Заголовки ответа (Response Headers):**
  * `Set-Cookie`: 
    * `JSESSIONID=<session_id>; Path=/ec-server; Secure; HttpOnly`
    * `route=<route_id>; Path=/ec-server`
* **Коды ответа:**
  * `200 OK`: Успешная авторизация.
  * `401 / Response Data: 1`: Неверный логин или пароль.
  * `Response Data: 3`: Требуется капча.
  * `Response Data: 4`: Учетная запись заблокирована.

### 1.2. Сессионные куки для последующих запросов
Во всех последующих HTTP-запросах необходимо передавать заголовок:
`Cookie: JSESSIONID=<session_id>; route=<route_id>; site_ver=app`

Если сервер возвращает `401 Unauthorized`, клиент автоматически выполняет повторный вход с сохраненными хэшированными учетными данными и повторяет запрос.

## 2. Профиль и состояние пользователя

### 2.1. Получение текущего состояния
* **Эндпоинт:** `GET /state?menu=false`
* **Описание:** Возвращает информацию об авторизованном пользователе, его роли, персоне и учебном заведении.
* **Пример ответа:**
```json
{
  "userId": 123456,
  "authenticated": true,
  "profile": {
    "firstName": "Иван",
    "lastName": "Иванов",
    "middleName": "Иванович",
    "email": "ivan@example.com",
    "phoneMob": "+79991234567"
  },
  "user": {
    "userId": 123456,
    "prsId": 654321,
    "roles": ["ROLE_STUDENT"],
    "currentPosition": {
      "orgId": 100,
      "orgName": "ГБОУ СОШ №1",
      "orgFullName": "Государственное бюджетное общеобразовательное учреждение...",
      "orgYearId": 2026
    }
  }
}
```

### 2.2. Профиль подопечных (для родителей)
* **Эндпоинт:** `GET /profile/{userId}/children`
* **Описание:** Если `roles` пользователя `ROLE_PARENT`, этот запрос возвращает список детей с их персональными `userId` и `prsId`.

## 3. Учебные периоды

### 3.1. Периоды обучения (четверти / триместры / год)
* **Эндпоинт:** `GET /dict/periods2?year={academicYear}` (например, `2026`)
* **Описание:** Список учебных периодов.
* **Структура элементов `items`:**
  * `typeCode: "Y"` — Академический год (`date1`, `date2`, `id`, `name`).
  * `typeCode: "HY"` — Полугодие.
  * `typeCode: "Q"` — Четверть / триместр (`id`, `name`, `date1`, `date2`, `num`).

## 5. Оценки и успеваемость

### 5.1. Журнал оценок за учебный период
* **Эндпоинт:** `GET /student/getDiaryPeriod?userId={userId}&eiId={periodId}`
* **Описание:** Список всех выставленных оценок за выбранный период обучения (`eiId`).
* **Пример ответа:**
```json
{
  "result": [
    {
      "lessonId": 1092831,
      "unitId": 42,
      "subject": "Алгебра",
      "mktWt": 1,
      "markVal": "5",
      "markNum": 5,
      "markDate": "2026-11-14T09:45:00",
      "lptName": "Самостоятельная работа",
      "teachFio": "Петрова А.В."
    }
  ]
}
```

### 5.2. Сводка по предметам и текущий средний балл
* **Эндпоинт:** `GET /student/getDiaryUnits?userId={userId}&eiId={periodId}`
* **Описание:** Текущие сводные показатели по каждому предмету.
* **Пример ответа:**
```json
{
  "result": [
    {
      "unitId": 42,
      "unitName": "Алгебра",
      "overMark": 4.75,
      "rating": "1/28",
      "totalMark": "5"
    }
  ]
}
```

### 5.3. Итоговые годовые оценки
* **Эндпоинт:** `GET /student/getTotalMarks?yearid={yearId}&userid={userId}&json=true`
* **Описание:** Итоговая ведомость оценок за все четверти/полугодия и год.

## 6. Файлы и вложения

### 6.1. Скачивание прикрепленных файлов
* **Эндпоинт:** `GET /files/{fileId}`
* **Заголовки:** `Cookie: JSESSIONID=...; route=...`
* **Возвращает:** Бинарное содержимое файла (PDF, DOCX, JPG, PNG).

## 7. Сообщения

Контракт проверен по `ChatSrv` официального веб-клиента
<https://app.eschool.center/scripts/scripts.js> и на тестовом аккаунте.
Все запросы используют существующие сессионные cookie; идентификаторы — числа.

| Операция | Запрос |
|---|---|
| Переписки | `GET /chat/threads?row=1&rowsCount=25&newOnly=false&starredOnly=false` |
| Следующая страница переписок | Тот же запрос с `msgNum` последней записи предыдущей страницы |
| Переписка | `GET /chat/thread?threadId=…` |
| История | `PUT /chat/messages?threadId=…&rowStart=1&rowsCount=25&getNew=false&isSearch=false`, JSON `{}` |
| Более ранняя история | Тот же запрос с `msgStart` — минимальным `msgNum` загруженной страницы |
| Получатели | `GET /usr/getUserListSearch` |
| Существующие личные диалоги | `GET /chat/privateThreads`, объект `{ "prsId": threadId }` |
| Создание личного диалога | `PUT /chat/saveThread`, JSON `{ "isGroup": false, "isAllowReplay": 2, "interlocutor": prsId }`, ответ — положительный `threadId` |
| Отправка | `POST /chat/sendNew`, multipart-поля `threadId`, `msgText`, `msgUID` |
| Прочтение сообщения | `GET /chat/readed?msgId=…` |
| Системный отправитель без ответа | `GET /chat/noreply`, ответ — `prsId` |

Переписки и сообщения возвращаются массивами. У переписки используются `threadId`,
`msgNum`, `senderId`, `senderFio`, `subject`, `msgPreview`, `showDate`,
`newReplayCount`, `dlgType`, `addrCnt`, `isAllowReplay`, а также необязательные
`closeDate`, `senderInvalid`, `adminIds`. Сообщение содержит `msgId`, `msgNum`,
`senderId`, `senderFio`, HTML в `msg`, время `showDate` в миллисекундах и `attachCount`.
Получатель содержит `prsId`, `fio`, необязательные `groupName` и `out`.

Текст при отправке экранируется как HTML, при показе отображается обычным текстом.
HTTP 200 недостаточно: отправка успешна только при положительном `msgId` и
неотрицательном `prsCount`. Отрицательные значения означают запрет ответа,
закрытый/удалённый диалог или другую ошибку. Автоматического повтора после сетевой
ошибки нет; черновик и `msgUID` сохраняются в памяти для повторной попытки с тем же текстом.
Официальный клиент передаёт `msgUID`; гарантия серверной идемпотентности не установлена.
Вложения в этом изменении обозначаются количеством, без загрузки файлов.

## 8. Уведомления

Периодическая работа WorkManager запускается при входе и старте приложения,
отменяется после выхода или отключения всех типов. Проверка выполняется примерно
раз в 15 минут при наличии сети; Android может откладывать её.

Настройки включают общий переключатель, отдельные переключатели оценок и ДЗ,
а также время напоминания (по умолчанию 08:00, часовой пояс устройства).
Старый общий запрет уведомлений сохраняется при обновлении.

Оценки обнаруживаются в общей синхронизации (также при обновлении открытого экрана).
Первая успешная синхронизация каждого аккаунта/периода создаёт базовое состояние,
включая пустой журнал. Ключи ранее обнаруженных оценок сохраняются отдельно от
состояния прочтения, поэтому повторная загрузка не создаёт дубли.

Напоминание о ДЗ сначала обновляет расписание и учитывает локальные отметки
выполнения, включая ожидающие отправки. Оно объединяет невыполненные задания на
текущую локальную дату в одно тихое уведомление без звука и вибрации. После успешного
показа сохраняется дата для аккаунта; повтор в этот день не выполняется. Если нет
заданий, сеть недоступна или уведомления запрещены, дата показа не фиксируется.
Нажатие открывает ДЗ независимо от состава нижнего бара.
